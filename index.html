01 — Concepts
What Is a Playbook?
01
Playbook
A YAML file that defines a set of plays — each play maps a group of hosts to a list of tasks to execute in order.
02
Task
A single unit of work in a play. Each task calls an Ansible module (like apt, copy, service) to do something on the remote host.
03
Module
Built-in tools Ansible uses to perform actions — install packages, copy files, manage services, create users, and much more.
04
Idempotency
Running a playbook multiple times produces the same result. Ansible only makes changes when the system is not already in the desired state.
02 — The Playbook
playbook.yml
ansible-playbook-project/deploy.yml
12345 678910 1112131415 16171819
---
---

- host: all
  become: true
  tasks:

    - name: Install apache httpd
      ansible.builtin.apt:
        name: apache2
        state: present
        update_cache: yes

    - name: Copy file with owner and permissions
      ansible.builtin.copy:
        src: index.html
        dest: /var/www/html
        owner: root
        group: root
        mode: '0644'
1
host: all
Targets every host in the inventory file — both EC2 instances will receive all the tasks in this play.
2
become: true
Elevates privileges to sudo so Ansible can install packages and write files to system directories on the remote hosts.
3
ansible.builtin.apt
The fully-qualified module name for the apt package manager. Installs apache2 and updates the cache in a single task.
4
ansible.builtin.copy
Copies index.html from your WSL machine into /var/www/html on the EC2 server — Apache's default web root.
5
owner, group, mode
Sets file permissions on the copied file. 0644 means the owner can read/write, everyone else can only read — standard for web files.

04 — Modules Used
Ansible Modules in This Playbook
📦
ansible.builtin.apt
Package Manager
Installs packages on Debian/Ubuntu systems. Used here to install apache2 with state: present and update_cache: yes in one task.
📋
ansible.builtin.copy
File Transfer
Copies index.html from your WSL control node into /var/www/html on the EC2 server — Apache's default web root directory.
🔐
owner & group
File Ownership
Sets the Unix owner and group of the copied file to root — ensuring the web server has proper access to serve the file.
🔢
mode: '0644'
File Permissions
Octal permission — owner can read & write, group and others can only read. This is the standard safe permission for web-served files.
⬆️
become: true
Privilege Escalation
Runs all tasks as sudo on the remote host — required for installing packages and writing into system directories like /var/www/html.
🌐
host: all
Host Targeting
Runs the play against every host defined in the inventory file — no need to specify a group, all managed EC2 nodes receive the tasks.
